# VnTool에서 연출 툴을 갈라 낸다

> 2026-10-28 소유자 결정: VnTool(`VNStoryEditor_avalonia`)은 **작가가 시나리오 문구·선택지 문구를 쓰는 곳**으로만 남긴다.
> 대사에 연출을 붙이는 일(무대 프리뷰 · 터미널 · 연출 추가 · 수치 인스펙터 · Setup 편집 · 에셋)은 별도 툴이 맡는다.
> 2026-10-29: 그 별도 툴이 이 저장소(`ked-story-director`)다. **이력째 옮기고, 작가 기능을 걷는다.**

## 1. 출처

| | |
|---|---|
| 원본 | `VNStoryEditor_avalonia` `dev` @ `f2a7bdc` (2026-09-18, "the chapter graph became a board") |
| 이 저장소 `main` | 위 커밋 그대로 — 이력 714커밋을 그대로 가져왔다 |
| VnTool 쪽 짝 | 같은 날 VnTool `dev`는 `1b29cf7`에서 연출 기능을 걷었다(`docs/plans/stage-removal.md` — VnTool 저장소) |

왜 `f2a7bdc`인가: VnTool `master`(`7e5f432`)는 9/15 판(`6630b26`)에 "제거 → 되돌림"만 얹은 것이라 `dev`의 9/15~9/18
125커밋(챕터 보드 · 대본 탭 · 직렬화 · 발행 결과 · 모델 변경)이 빠져 있다. 연출 툴은 VnTool이 발행한 대사 결과를 읽어야 하므로
프로젝트 형식이 지금의 VnTool과 같은 쪽에서 출발한다(소유자 확인, 2026-10-29).

## 2. 결정

| # | 항목 | 결정 |
|---|---|---|
| D1 | 옮기는 방식 | **이력째.** 연출 코드의 이력(blame · log)이 살고, 출발점이 빌드되는 상태다 |
| D2 | 무엇을 하나 | VnTool이 연출을 걷었듯 **반대로 작가 기능을 걷는다** |
| D3 | 데이터 경계 | 두 편집기가 한 파일을 쓰지 않는다. **대사의 주인은 VnTool**이고 이 툴은 VnTool이 발행한 대사 결과(라인 ID 포함)를 **읽기만** 한다. 연출은 이 툴의 파일에 산다. 산출물은 `Story_*.yarn`이 VnTool, `Pres_*.yarn`이 이 툴(지금도 따로 나가고 `<<pres_start>>`로 잇는다) |
| D4 | 가지 | 작업 `dev`, 기본 `main`. amend · force-push 금지 |
| D5 | 무대 프리뷰 · 에셋 탐색기 | 따라온다 — 작가는 안 쓰지만 연출가의 화면이다 |

## 3. 단계

한 단계 = 커밋 하나(또는 몇 개), CI(Windows) 녹색을 보고 다음으로.

| | 무엇 | 상태 |
|---|---|---|
| S0 | 이력 옮기기 · CI를 `main`·`dev`에 · 이 문서 | 이번 |
| S1 | VnTool `f2a7bdc` 뒤의 변경 중 연출에 해당하는 것 반입 — 연출 카탈로그를 런타임 배경 리그 제거에 맞춘 것(VnTool `5693f9d`) | |
| S2 | 데이터 경계(D3) 조사 · 계약 — VnTool이 무엇을 어디에 발행하는지(대사 결과 보관소 · 라인 ID), 이 툴의 연출 파일 형식, 내보내기 분담 | |
| S3 | 작가 기능 걷기 — 대본 탭 · 챕터 보드 편집 · 엑셀 쓰기 · 화자/스탯 등록 등. 목록은 S2 뒤에 확정 | |
| S4 | 이름 — 앱 이름 · 솔루션 · exe · 문서의 "VnTool". 네임스페이스(`Vn.*`)를 바꿀지 | |
| S5 | VnTool `dev`에 남은 연출 뼈대(연출 노드 · 커맨드 모델 · 연출 발행 · Yarn 연출 출력 · 카탈로그) 걷기 — 이 툴이 그 일을 넘겨받은 뒤 | |

## 4. 열린 것

- 반입 `Ked.Presentation.Core`는 옛 재생 저장소 판(2026-08-20)이다. 정본은 이제 `ked-stage-runtime`이다 — 언제 갈아탈지.
- `<<motion>>`: 런타임에 있고 카탈로그에 없다. 연출 툴의 일이므로 여기서 다룬다(모션 이름은 `ked-motion-tool`이 내는 `motions.json`에서).
