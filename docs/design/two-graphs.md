### 2.2 사용자 동작

모든 편집은 `ProjectEditor`를 지나고 되돌리기는 프로젝트 스냅샷이다. Ctrl+Z/Y/S는 창 전역이고, **글자 칸에 초점이
있으면 Z/Y를 가로채지 않는다**(`MW` 254-287). Delete 키 · Esc · F1 · 판의 우클릭 메뉴는 없다.

| 동작 | 결과 |
|---|---|
| 카드 클릭 / 끌기 | 선택 / 끄는 동안은 화면만, **놓을 때 `MoveEpisodes` 한 번**(되돌리기 한 칸) |
| 카드 더블클릭 | 대본 엑셀을 연다(없으면 만든다) — D2에서 걷는다 |
| 휠 / 가운데 단추 끌기 | 커서 기준 확대(0.3~2.5) / 판 이동 |
| 선 · 문구 · 점 클릭 | 간선 패널. 분기 점선 클릭은 분기 패널 |
| [＋ 에피소드] | `new01…` 발급. 고른 것(없으면 마지막)의 다음으로 `AddNextEpisode` — 에피소드 · 카드 · 대본 · 간선(문구 `계속`)이 **한 Mutate** |
| [자동 정렬] | `ChapterBranchPlanner.Layout`을 `MoveEpisodes` 한 번으로 |
| [에피소드 삭제] | 끝점 간선 · 픽스처 참조 · 카드까지 함께 걷는다 |
| 이름 칸 Enter | 에피소드 개명 — 간선 · 픽스처 · 카드 이름이 따라간다. `cleared:` 참조가 있으면 거부 |
| 선택지 [＋] · 줄 클릭 · [잇기]/[수정] · ✕ | 한 줄 폼을 열고 닫는다 · `AddEdge`/`SetEdgeRoute`(순서를 지킨다) · `RemoveEdge`(문구 사전은 남는다) |
| 간선 패널의 콤보 | 고르는 즉시 `UpdateEdge`. 글자 칸(잠금 안내문 · 스탯 수치)은 초점을 잃거나 Enter일 때 |
| 분기 조건 콤보 | `SetEntryCondition` — 첫 줄 `BeginIf` + 꼬리 `EndIf`를 한 Mutate로. 손으로 지은 구조면 칸이 잠기고 사유를 말한다 |
| [챕터] 조건 · 스탯 | 식 · 표시이름 · 범위 · 타입. 스탯 키는 ✎로만(세이브 열쇠라 경고를 먼저). 지울 때 쓰는 곳이 있으면 목록을 보인다 |

### 2.3 배치

- 자리의 주인은 에피소드의 X·Y다(v4, 2026-09-18). 그리기는 그 값을 덮지 않는다. 카드가 한 점에 포개져 있을 때만
  `Layout`을 **빌려** 보이고, 첫 끌기 때 판 전체 자리를 함께 적는다.
- 포트(v5): **선택지는 아래, 분기는 오른쪽, 들어오는 길은 위 가운데 점 하나.** 연출 그래프와 손놀림을 맞춘 것이다.
- ⚠ **흐름 방향이 섞여 있다.** [자동 정렬]과 새 카드 자리(`SuggestPlacement`)는 깊이를 **X축**(열 220 · 줄 150)으로
  편다(`ChapterBranchPlanner.cs` 3-5, 97-114, 125-160). 포트는 위→아래인데 자동 배치는 왼→오다. 소유자 화면의
  위→아래는 사람이 끌어 놓은 것이다. §7 D3에서 함께 맞춘다.

### 2.4 검증 · 내보내기

- 프로젝트가 바뀔 때마다 재읽기가 한 UI 차례에 한 번으로 합쳐 돈다: 전 챕터 진행 JSON 자동 내보내기 → 고른 챕터 검증 →
  그리기(`CGV` 1139-1176, 379-393).
- 검증 = 모델 진단(스탯 범위 · 조건식 · 자동 길 · 장면 입구) + 판에 대사 노드가 있는가 + 줄 없는 노드 + 도달성 증명
  (상태 상한 250,000, 다 못 훑으면 오류가 아니라 알림). 증명은 모델 내용으로 캐시한다(VnTool C3).
- 내보내기는 검증을 통과한 챕터만, 진행 코어 로더에 실어 본 뒤, 바이트가 다를 때만 `exported/{챕터}.progression.json`에
  쓴다. 출시 기준선 대비 선택지 순서가 바뀌면 막는다.

### 3.2 사용자 동작

| 카드 클릭 · 끌기 · 고무줄 | 선택 / **포인터가 움직일 때마다 `MoveNode`**(되돌리기 기록 없음, §6) / 무리 선택 |

### 3.3 배치 — 지금은 왼→오

- 저장되는 것은 노드마다 `Layout{X,Y}` 하나다. 프레임 · 장면 영역 · 레일 · 포트는 그릴 때마다 계산한다.
- **새 카드 자리는 `NodePlacement.For` 한 벌**이다(`src/Vn.Authoring/Graph/NodePlacement.cs`). 같은 장면에 이웃이 있으면
  **그 줄의 오른쪽 끝**(maxX + 320, minY), 장면이 비어 있으면 **(0, 장면 차례 × 260)** — 장면은 줄로 아래로 쌓이고
  장면 안의 진행은 오른쪽으로 간다. ⚠ 이미 선 카드는 옮기지 않는다.
- 레일(챕터 간선): 줄기가 카드 왼쪽+30에서 아래로 내려가고, 칩(선택지 칸)이 세로로 쌓이고, **가로 레인이 도착 카드의
  왼쪽 접점**으로 들어간다(`GEV` 561-1181). 실행 간선(IF 갈래 · 분기)은 카드 오른쪽 포트 → 도착 카드 왼쪽,
  가로-세로-가로 직교선이다(`OrthogonalEdgeRouter`).
- 「분기 추가」의 새 카드는 원본 **바로 아래**(Y + 260)에 선다(`PE` 428-433).

### 3.4 대사 본문이 카드에 닿는 길

- 카드는 본문을 그리지 않는다. 노드는 `ScriptId`로 `ScriptDocument`를 가리키고, 노드 자신은 LineId에 붙는 논리(갈래 ·
  분기 표식)만 든다.
- 글은 세 창구에서 들어온다: 대본 탭(한 칸 글 + Ctrl+S, `ApplyScenarioText`) · 곁기둥(줄마다 칸, 글자마다
  `SetScriptLineText`) · [대본 가져오기](엑셀).
- `SetScriptLineText`는 바뀔 때마다 Mutate 한 번이다 — **글자마다 되돌리기 한 칸**, 칸마다 프로젝트 직렬화. 반면
  `ApplyScenarioText`는 `ScriptSynchronizer`의 diff로 **LineId를 지키며** 한 번에 넣는다(애매하면 거부, 삭제는 확인).
- 갱신 계획(`ProjectRefreshPlanner`): **`DialogueContent`는 그래프를 다시 그리지 않는다** — 카드 안에 글자 칸을 둬도
  타이핑으로는 부서지지 않는다. `Structure` · `Connections` · `Results` 등은 `Graph.Rebuild`가 판을 비우므로
  **초점 잡힌 칸이 사라진다**. 줄 추가 · 삭제 · 이동은 `Structure`다.

## 4. 두 그래프가 함께 쓰는 것

| 무엇 | 규칙 |

## 5. 다시 쓸 때 지킬 것

### 데이터

1. **각 값의 주인은 한 곳이다.** 같은 사실이 두 곳에 있으면 어긋나고, 어긋남은 최종 출력에서야 드러난다. 창구가
   둘인 것은 괜찮다(간선) — 사본이 둘인 것이 안 된다.
2. **LineId는 영구 불변이다.** 세이브 · 연출 바인딩 · 번역이 걸려 있다. 글을 다시 넣을 때는 diff로 신원을 잇고, 확신이
   없으면 거부한다. 줄을 지우면 은퇴시키고, 은퇴하면 그 줄의 분기 표식도 접힌다.
3. **간선 순서 = 화면 순서 = 런타임 `OptionIndex`.** 출시된 선택지 사이에 끼우거나 옮기면 과거 플레이 이력의 뜻이 바뀐다.
   이어진 칸을 옮길 때는 순서를 지키는 `SetEdgeRoute`를 쓴다.
4. **스탯 키는 세이브 열쇠다.** 고치는 칸을 두지 않고, 바꿀 때는 경고를 먼저 보이고 쓰는 곳을 함께 끌고 간다.
5. **계산은 저장하지 않는다.** 포트 · 레일 · 프레임 · 검증 · 도착 스탯은 매번 계산한다.
6. **분기 조건은 툴이 아는 모양(첫 줄 `BeginIf` + 꼬리 `EndIf`)만 쓴다.** 손으로 지은 구조는 읽기만 한다.

### 편집 · 되돌리기

7. **사용자 동작 하나 = `Mutate` 하나 = 되돌리기 한 칸.** 둘로 쪼개면 한 번 물렀을 때 반쪽이 남는다(분기 조건이 실사례).
   끌기는 놓을 때 한 번만 적는다.
8. **바뀐 것이 없으면 Mutate하지 않는다.** 같은 값의 Mutate가 화면을 다시 만들어 쓰던 칸을 부쉈다(2026-08-24).
9. **글자 칸은 초점을 잃거나 Enter일 때 넣는다.** 자판마다 넣으면 되돌리기와 재계산이 폭주한다. 저장 · 자동 저장은 안
   넣은 글을 먼저 밀어 넣는다(`MW.FlushPendingEdits`).
10. **패널을 채우는 동안은 자동 저장을 막는다**(`_fillingPanel`). 화면을 그리는 일이 저장을 부르면 아무것도 안 고쳤는데
    파일이 써진다.
11. **되돌리기는 스냅샷을 새로 푼다.** 들고 있던 노드 객체는 낡으니 Id로 다시 찾는다.

### 화면

12. **내용 변경과 구조 변경을 구분해 알린다.** 글자 편집이 편집 칸을 다시 만들면 안 된다(`ProjectRefreshPlanner`).
13. **클릭 처리기 안에서 판을 다시 만들지 않는다.** 더블클릭과 끌기가 죽는다.
14. **이미 선 카드는 옮기지 않는다.** 자리는 사람이 정한다. 새 카드의 첫 자리 규칙은 한 벌로 둔다. 판 전체를 다시 세우는
    일은 사람이 누르는 단추([자동 정렬])이고 되돌리기 한 칸이다.
15. **챕터 선택은 한 길로 지난다.** 드롭다운만 다른 길로 가던 때 검증이 이전 챕터의 것으로 남았다.
16. **재읽기는 합친다.** 동기화 한 번에 재읽기 123번, 첫 화면 58초였다. 고정도 시간이 아니라 일의 횟수로 건다.
17. **떼는 길이 있어야 한다.** 닫힌 뷰의 타이머가 죽은 디스패처에 Post하면 프로세스가 내려간다.
18. **삭제 단추는 늘 같은 자리에 있고, 무엇을 지우는지 이름으로 말한다.** 우클릭으로는 지우지 않는다(연출 그래프의 간선
    우클릭 삭제가 유일한 예외다).
19. **조용히 버리지 않고, 추측으로 고쳐 주지 않는다.** 못 그린 것은 보이게 남기고, 오타는 그 자리에서 오류로 말한다.
20. **잘된 일은 조용하다.** 상태줄 · 검증 보고는 문제가 있을 때만 말하고, 잠금 같은 상태가 그대로면 같은 말을 되풀이하지
    않는다.

### 출력 · 검증

21. **결정적 출력이 계약이다.** 같은 입력은 바이트가 같아야 한다(서버가 SHA-256으로 버전을 식별). 컬렉션 순서를 바꾸는
    리팩터링에 주의한다.
22. **소비자의 실제 코드에 실어 본다.** 진행 JSON은 진행 코어 로더에, Yarn은 실제 컴파일러에 통과해야 나간다.
23. **진행 스탯을 Yarn 변수로 읽지 않는다.** 도달성 증명 밖에 숨은 분기가 생긴다.

### D3 — 연출 그래프를 위→아래로

> *"챕터 그래프처럼 위에서 아래로 진행시키도록 합니다."* · *"분기는 기존처럼 오른쪽으로 빠지도록 하십시오. 특정 에피소드를
> 끝까지 진행했을 때, 나오는 선택지에서 골라서 가는 것들을 아래로 향하게 합니다. 챕터그래프의 형태를 참고해서."*

| 무엇 | 지금 | 바꾼 뒤 |
|---|---|---|
| 선택지로 가는 다음 에피소드 | 같은 장면 줄의 **오른쪽** | 부모 카드의 **아래**. 자리가 차 있으면 오른쪽으로 비켜 선다 |
| 분기로 다녀갈 카드 | 원본 **아래**(Y + 260) | 원본의 **오른쪽** |
| 레일(선택지 선) | 칩 → 가로 레인 → 도착 카드 **왼쪽** | 칩은 지금처럼 카드 아래에 쌓이고, 레인이 **아래로** 내려가 도착 카드 **위 가운데** 입구로 |
| 분기 · IF 갈래 선 | 카드 오른쪽 → 도착 왼쪽 | 그대로 — 오른쪽으로 빠진다 |
| 챕터 프레임 · 장면 프레임 | 카드만 감싼다 | 카드 아래 레일까지 감싼다 |
| 이미 선 판 | — | 연출 그래프에도 **[자동 정렬]**(판 하나를 위→아래로 다시 세우고 되돌리기 한 칸). 이미 선 카드는 저절로 옮기지 않는다(§5-14) |
| 끌기 | 포인터마다 `MoveNode` | 놓을 때 한 번 적고 되돌리기 한 칸(§6-2) |
| 챕터 그래프 | 자동 정렬 · 새 카드 자리가 왼→오 | 깊이를 **Y축**으로 — 두 판이 같은 방향으로 선다(§6-4) |

선택지 칸은 카드 **아래**에 그대로 둔다(2026-09-16 소유자). 칸을 챕터 그래프처럼 아래변의 점으로 줄이면 한 칸 폭이

### D4 — 대사 노드 안에서 쓴다

> *"각각의 대사노드는, 이제 다른 엑셀이나 대본탭에서 작성한 것을 반영하는 게 아니라, 노드 안에 텍스트 공간이 있고
> 그곳에 직접 글을 작성하는 것까지를 목표로 합시다."*

- **카드 안에 여러 줄 글 칸 하나.** 한 줄이 대사 한 줄이고 `화자: 대사`로 쓴다(화자가 없으면 지문). 걷는 대본 탭의 쓰기
  방식(자유 편집 + 넣기)을 카드로 옮기는 것이다.
- **넣는 때는 초점을 잃을 때와 Ctrl+S.** 넣는 길은 `ApplyScenarioText` — diff로 LineId를 지킨다(§5-2). 줄마다 칸을
  두는 안은 줄을 더할 때마다 구조 변경이 판을 다시 그려 초점이 사라지고, 글자마다 되돌리기가 쌓여 버린다.
- 넣기 한 번이 되돌리기 한 칸이 되게 `ApplyScenarioText`의 여러 Mutate를 하나로 묶는다(§5-7).
- 함정(조사에서 확인):
  - 카드 더블클릭이 무대 탭으로 튀고 카드 누르기가 끌기를 시작한다 — 글 칸 안의 누르기는 카드로 올려 보내지 않는다.
  - 휠은 판의 확대가 가로챈다 — 글 칸 위에서는 칸이 스크롤한다.
  - 카드 높이를 어림하는 공식(`CardHeightOf` · `NodeAt`)에 글 칸 높이를 넣어야 레일 · 프레임이 어긋나지 않는다.
  - 곁기둥 대사 편집기와 같은 글을 본다 — 어느 쪽에서 넣든 다른 쪽이 낡은 글로 덮어쓰지 않게 한다.
  - 넣기 전에 다른 노드를 고르거나 저장하면 안 넣은 글을 먼저 넣는다(`FlushPendingEdits`).
  - **새 카드는 빈 줄 하나를 들고 선다.** 그 카드에 `ApplyScenarioText`로 두 줄 이상을 넣으면 "빈 줄을 고친 것인지 지운
    것인지 모른다"로 반영 전체가 거절된다(D2 테스트 변환에서 다섯 에이전트가 모두 걸렸다 — 테스트는 줄 명령으로 피했다).
    카드 글 칸의 첫 넣기는 이 경우를 풀어야 한다: 빈 줄 하나뿐인 대본은 그 줄을 첫 줄로 고친 것으로 본다.
